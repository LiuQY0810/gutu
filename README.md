# 展品故事页（扫码打开）

给屏上二维码用的落地页。手机扫码 → 打开这一页 → 看照片和故事。

## 文件

| 文件 | 说明 |
|---|---|
| `index.html` | 沈家老屋（锚点 01）。**单文件**，CSS 全内联，不依赖任何外部资源，弱网也能秒开 |
| `assets/hero.jpg` | 头图 1100×924，从原始素材 `DW_buddy\assets\art\纪实摄影_…厅堂内部…png`（1024×1024）重裁，已切掉右下角 AI 水印 |
| `assets/detail_*.jpg` | 4 张局部特写（天井 / 八仙桌 / 柱础 / 檐下红椒），同一张源图裁出来的 |
| `assets/audio/story.m4a` | 口述录音，56 秒，AAC 128k 单声道 |
| `qr_tool.py` | 把网址写进屏的二维码缓冲区，并导出一张可扫描的二维码图 |

> ⚠️ 早期版本的头图是从**展品页截图**里裁的，右边缘会带出屏上的「类别 / 北纬 / 天井…」文字。
> 现在改用原始素材（`DW_buddy\assets\art\` 下那三张 1024×1024 图，没有界面文字）。
> 重新生成：`python tools\make_web_images.py`。

## 先本地看一眼

直接双击 `index.html`，浏览器打开就行（手机可以用微信/浏览器扫本地文件？不行——**扫码必须走网址**，本地文件只能你自己看效果）。

手机预览的最快办法（同一个 WiFi）：

```bash
cd web
python -m http.server 8000
# 然后在手机浏览器输入 http://<电脑的局域网IP>:8000
```

Windows 查 IP：`ipconfig`，看「IPv4 地址」。

## 发布到公网（三选一）

### 方案 1：GitHub Pages（免费、稳定、推荐）

1. 注册 GitHub 账号
2. 新建仓库，比如 `gutu-compass`
3. 把 `index.html` 和 `assets/` 传上去（网页上拖拽即可）
4. 仓库 → `Settings` → `Pages` → Source 选 `main` / `/(root)` → Save
5. 等 1 分钟，网址是：

```
https://<你的用户名>.github.io/gutu-compass/
```

6. 想以后加樟树、水碓房：复制 `index.html` 成 `02.html`、`03.html`，网址就变成 `.../gutu-compass/02.html`

> 长度约 40–50 字符，稳稳塞进屏的 64 字节缓冲区。

### 方案 2：阿里云 OSS / 腾讯云 COS 静态网站

国内访问快，但要实名认证，默认域名较长（可能 60+ 字符），**要先量长度**。

### 方案 3：本地局域网（演示兜底，不推荐正式用）

电脑或 MaixCAM 上跑 `python -m http.server 8000`，手机连同一 WiFi，网址是
`http://192.168.x.x:8000`。缺点是**换网络 IP 就变**，二维码内容得跟着改（见下）。

## 把网址写进屏

```bash
cd web
python qr_tool.py --url "https://你的用户名.github.io/gutu-compass/"
```

它会：
1. 检查长度（网址 + 2 字节结束符 ≤ 64 字节）
2. 生成 `qr_preview.png`，你可以先自己扫一下确认能打开
3. 把网址写进 `DGUS工程文件\DWIN_SET\22_Config.bin` 的 `0x1200`（文件偏移 `0x2400`），并自动备份成 `.bak`

然后**烧 `22_Config.bin`**，P05 的二维码内容就变了——控件一个字都不用动。

> 只检查、不改文件：加 `--dry-run`。

## 尺寸说明

| 内容长度 | 二维码单元数 | 屏上实际大小（单元 4px） |
|---|---|---|
| 34 字节（常见短网址） | 29×29 | 116×116 像素 |
| 60 字节 | 约 37×37 | 148×148 像素 |
| 超过 155 字节 | 45×45 | 180×180 像素（P05 的框刚好） |

二维码小于 45 单元时会显得比 180 的框小一圈，这是正常的（留了静默区）。
如果想让二维码更大更好扫，可以把 P05 那个二维码控件的「单元像素」从 4 改成 5
（29 单元 → 145 像素，仍小于 180），但**别改到 6**，否则 37 单元的会超出框。

## 声音档案（页面上那一段）

页面里有一块「声音档案」，用手机扫码就能听——**这也是补上"现场屏没有喇叭"的唯一办法**。

放录音的步骤：

1. 手机自带录音机，录 **40–90 秒**方言讲述（坐着、安静房间录，别贴太近，会喷麦）
2. 导出成 `m4a` 或 `mp3`，改名 `story`，放到：

```
web/assets/audio/story.m4a      （iPhone 直接是 m4a）
web/assets/audio/story.mp3      （安卓建议转 mp3，amr/3gp 兼容性差）
```

3. 页面会自动认出，播放器出现，提示消失

**没放录音时**：播放器会藏起来，显示一行"录音还没放进来"，版式不会塌——所以现在就能先发布看效果。

### 实际用的处理链（`tools\process_story_audio.py`）

手机录音原始通常偏小声、结尾突断。交给脚本就行：

| 步 | 做什么 |
|---|---|
| 1 | 解码成单声道 48 kHz |
| 2 | 裁掉首尾多余静音（开头留 0.25 s、结尾留 0.15 s） |
| 3 | 增益 +4 dB，再用**软膝限幅**（门槛 0.42）压住峰值，避免削顶 |
| 4 | 峰值归一到 **-1 dBFS** |
| 5 | 结尾 **0.6 s 平方曲线淡出** + 补 0.5 s 静音 |
| 6 | 编码 AAC 128k / 48k / **单声道**（语音够用，体积减半） |

实测把一段手机录音从 **-23.5 dBFS 提到 -19.4 dBFS**，信噪比 54 dB（环境很干净，没做降噪）。

> 工具链用的是 `imageio-ffmpeg` 自带的 ffmpeg（`pip install imageio-ffmpeg`），不用另外装。

**改文案**：`index.html` 里这三处

| 位置 | 改什么 |
|---|---|
| `.audio-meta` 里的 `天井里的那些年` | 音频标题 |
| 同一段的 `村中长者口述 · 方言 · 约 1 分钟` | 讲述人 / 语言 / 时长 |
| `<p class="transcript" id="transcript">` | 文字稿（建议 2–3 句，太长没人看） |

音频建议 **5 MB 以内**（90 秒 mp3 约 1.5 MB），4G 下也能秒开。

## 坐标：以装置为准，别再手写

页面上的经纬度必须和 `scene_gate.py` 里 `ZONES` **完全一致**，否则会出现「屏上说到了、导航带去别处」。

早期就是两处各写一份，结果差了 **4.48 公里**。现在用一个脚本同步：

```bash
python tools\sync_web_coord.py 0     # 同步 ZONES[0] 沈家老屋
python tools\sync_web_coord.py 1     # 同步 ZONES[1] 村口樟树
```

它会把页面上**三处文字**（页头 / 档案 / 到这儿来）和**三个地图链接**一起刷新。

### 坐标系别搞混

| 谁 | 坐标系 |
|---|---|
| 北斗 ATGM332D | **WGS-84** |
| 高德 | GCJ-02（火星坐标） |
| 百度 | BD-09 |

直接把 WGS-84 传给高德/百度，在国内会**再偏 300–500 米**。所以链接里必须写死：

```
高德：&coordinate=wgs84
百度：&coord_type=wgs84
```

页面上的坐标后面也标了 `WGS-84`，别再改掉。

### 三个地图按钮的区别

| 按钮 | 用的接口 | 行为 |
|---|---|---|
| **高德导航** | `uri.amap.com/navigation` | 直接进路线规划 |
| 高德看位置 | `uri.amap.com/marker` | 只标注点，不规划路线 |
| 百度地图 | `api.map.baidu.com/marker` | 备用 |

三者都带 `callnative=1`，手机上会直接拉起各自的 App。

## 推送推不上去怎么办（`Failed to connect to github.com port 443`）

**症状**：`git push` 报 `Failed to connect to github.com port 443 after 21084 ms`，
但 `ping` / `Test-NetConnection` 有时又通。

**真因**：DNS 把 `github.com` 解析到 `20.205.243.166`，这个 IP 的 443 被阻断；
而 `140.82.112.3`、`140.82.113.3`、`20.27.177.113` 都能通。

**解法**：`tools\gh_proxy.py` 是一个极简 CONNECT 代理，把 `github.com:443` 转到能通的 IP 上，
TLS 的 SNI 仍是 `github.com`，证书校验照常通过。

```bash
python tools\gh_proxy.py                                   # 另开一个窗口
git -c http.proxy=http://127.0.0.1:8443 push
```

代理日志里能看到 `[通过] github.com:443 -> 140.82.112.3`。

## 日常更新流程（记住这三条）

| 你改了什么 | 要做什么 | 二维码要重烧吗 |
|---|---|---|
| 页面文字、照片、加录音 | `git add . && git commit -m "改了什么" && git push` | **不用**，网址没变 |
| 换了仓库名 / 换了托管 | 重跑 `qr_tool.py --url "新网址"`，烧 `22_Config.bin` | 要 |
| 只想预览 | `python -m http.server 8000`，手机连同一 WiFi 打开 `http://电脑IP:8000` | 不用 |


推送后一般 **1 分钟内**生效；手机没看到变化就强制刷新（或换个浏览器）。
